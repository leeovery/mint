- FINDING: MetadataLevel.String() collapses the shared scope and an invalid out-of-range level onto the same empty-string value
  SEVERITY: low
  FILES: internal/config/metadata.go:64-77, internal/setupguide/setupguide.go:354-359
  DESCRIPTION: String() returns "" for both LevelShared (a legitimate, expected scope: the top-level shared keys) and the default branch (any int outside the four declared constants — i.e. a bug, a corrupted/uninitialised level). Two semantically opposite cases — "this is correctly the shared level" and "this level value is not a real MetadataLevel" — produce one identical output. The render seam then maps that empty string to the "top-level" placeholder (LevelCell), so an out-of-range level would silently render as a valid shared-level cell in the agent-facing config table rather than being caught. The level identity is described as a "closed, typed identity that the render target and the drift test agree on", but the closure is not actually enforced: an unrecognised level reads as shared. This is latent rather than active because every row in MetadataRows() uses a declared constant today; it becomes a real masking bug only if a fifth level is added without a String() case. Proportionally low because the SoT rows are hand-authored and drift-pinned, so an undeclared level cannot enter through the schema.
  RECOMMENDATION: Make the default branch distinguishable from LevelShared — e.g. have the default case panic (the same "fail loud on an impossible enum value" posture the bijection walk already takes when it t.Fatalf's on an uncovered container) or return a sentinel like "?invalid-level?" that the render and any future caller cannot mistake for the shared scope. Keep LevelShared returning "" (its real TOML form), so only the genuinely-invalid case changes behaviour.

  SEVERITY: low
  FILES: cmd/mint/main.go:105-108, cmd/mint/setup_test.go:16-29, cmd/mint/dispatch_test.go:80-91
