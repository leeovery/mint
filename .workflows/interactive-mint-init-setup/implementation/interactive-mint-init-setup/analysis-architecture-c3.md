- FINDING: max_diff_lines SoT default is a re-typed literal, not a drift-pinned carrier of its canonical const
  SEVERITY: medium
  FILES: internal/config/metadata.go:127, internal/config/config.go:68, internal/config/metadata_test.go:381, README.md:205
  DESCRIPTION: The spec's "initgen scope of change" section is explicit: "The SoT `default` column becomes the drift-pinned carrier of those values. No default value is left unpinned by the change." Two of the three shared scalar defaults honour this — `ai_command` and `timeout` source their SoT cells from the EXPORTED `config.DefaultAICommand` / `config.DefaultTimeout` constants (metadata.go:126,128), and each has a dedicated subsuming drift pin (TestMetadataRows_SharedAICommandDefaultEqualsConfigConstant / TestMetadataRows_SharedTimeoutDefaultEqualsConfigConstant) that fails the build if the SoT cell drifts from its constant. `max_diff_lines` breaks this pattern: the canonical default lives in the UNEXPORTED `defaultMaxDiffLines = 50000` (config.go:68), so the SoT row hardcodes the literal string `"50000"` (metadata.go:127) instead of sourcing the constant, and TestMetadataRows_ConcreteScalarDefaultsRenderVerbatim (metadata_test.go:381) pins it against another bare `"50000"` literal rather than the const. The value `50000` is now re-typed independently in four places — the const, the SoT cell, the SoT test, and the README table (README.md:205) — with NOTHING coupling them. The architectural inconsistency is the latent risk: this is the one shared scalar default the SoT does NOT pin to its source, so a future change to `defaultMaxDiffLines` would silently diverge from the agent-facing config reference (and the README) while the bijection/value tests stay green — exactly the drift the SoT was built to prevent, and exactly the "no default left unpinned" guarantee the spec made. The bijection test only guards key PRESENCE per (level, key), not default VALUES, so it gives no cover here.
  RECOMMENDATION: Export the constant (rename `defaultMaxDiffLines` → `DefaultMaxDiffLines`, updating its four in-package uses at config.go:309,645 and the comments), source the SoT cell from it (`Default: strconv.Itoa(DefaultMaxDiffLines)`), and add a subsuming pin in metadata_test.go tying the cell to the constant — symmetric with the existing ai_command/timeout pins. This closes the one remaining unpinned default and makes the "SoT default column is the drift-pinned carrier" invariant total across all three shared scalars, as the spec requires.
SUMMARY: The setup-guide / SoT / drift-test architecture is otherwise excellent — clean seams (config owns the SoT, setupguide renders it through one config-importing path, configtest is a zero-production-cost shared test seam, the cmd layer stays thin and version/setup share an IO-only no-ctx shape), well-scoped public surface, strong integration coverage (the run([setup]) end-to-end stdout/stderr-split test, SoT-row-driven render assertions), and sound type-safe boundaries (the closed MetadataLevel enum with enforced out-of-range distinguishability). The single structural gap is that max_diff_lines is the lone shared scalar default left out of the SoT's drift-pin discipline, re-typed as a literal in four uncoupled places against the spec's explicit "no default value is left unpinned" guarantee.
