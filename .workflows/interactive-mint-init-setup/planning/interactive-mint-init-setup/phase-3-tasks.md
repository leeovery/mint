### Task 3-1: Strip MintTOML() to the minimal template (empty body + dual-pointer header) and swap in the minimal-shape tests

**Problem**: The generated `.mint.toml` currently carries a full commented template — common keys active at their defaults plus every optional key present-but-commented with inline explanations. Pre-pivot that template was the only in-repo config documentation, so the duplication earned its keep. Post-pivot the binary is the doc source (`mint setup`'s SoT config reference for the agent; the GitHub docs / README for humans), so every comment and example value in the template is pure duplication — exactly the drift surface mint already fights with its `initgen`↔`config` pins. The template must be stripped to bare essentials so there is no second copy of the config docs to drift.

**Solution**: Change `initgen.MintTOML()` to return the decided minimal template — an **empty body** (no active keys, no commented example keys) plus a **short header comment** carrying two pointers: (a) the GitHub docs for the human config reference, and (b) `mint setup` for AI-assisted setup. The header is the cold-arrival recovery net: an agent or human who opens `.mint.toml` directly, without having read `mint setup`, still finds where the config reference lives — so the header is load-bearing and BOTH pointers are pinned by a test. Simultaneously remove the commented-template test assertions (they assert content the minimal template no longer carries) and replace them with tests asserting the minimal shape: the body is empty and the header carries both pointers. Update the package-level and function-level WHY-comments so the doc block describes the as-built minimal template (no stale "commented template" / "uncomment to enable" claims), per CLAUDE.md's comments-true-to-as-built rule.

**Outcome**: `initgen.MintTOML()` returns an empty-body `.mint.toml` whose only content is a header comment naming both the GitHub docs and `mint setup`; the `initgen` test package proves the minimal shape (no active or commented config keys in the body) and pins both header pointers; `ReleaseShim()`, the shim tests, and the engine init suite are unchanged and stay green.
