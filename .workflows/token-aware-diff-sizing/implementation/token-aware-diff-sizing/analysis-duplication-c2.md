  SEVERITY: low
  FAILURE: Take an operator who releases, or regenerates to a changelog target, with `--notes-file` pointing at a file inside the repo whose name holds a single quote, such as `notes/what's-new.md`. The run fails before the push, and the reset that should restore the starting state fails too, for example on a `.git` lock held past the Mutator's retry budget. The "unwind incomplete" warning then tells them to run `` `git restore --source=<sha> --staged --worktree -- ':(top,literal,exclude)notes/what's-new.md'` ``. Pasted into a shell, the `'` in the path ends the quote early. With one `'` the shell is left inside an unterminated quote and waits for more input. With two, as in `notes/'draft'.md`, the quotes balance but the pathspec now names a different path (`notes/draft.md`), so the restore also rewrites the notes file the keep-out exists to protect, and its uncommitted edits are lost. Either way, the printed step fails while the repo is half-unwound, the one moment the operator depends on it. No test uses a path holding `'`, so the suite stays green.
