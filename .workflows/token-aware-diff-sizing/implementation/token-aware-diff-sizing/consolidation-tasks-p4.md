# Consolidation Tasks: Token Aware Diff Sizing (Phase 4)

## Task 1: Pin the diff prefixes so saved notes and piece framing name real paths
placement: phase 4
severity: behaviour

**Problem**: The release diff takes its file headers in whatever form the operator's git config gives. Under `diff.noprefix = true`, or custom `diff.srcPrefix`/`diff.dstPrefix`, a header is not `a/P b/P`, and `headerPath` (`internal/notes/chunk.go:287-312`) returns it whole. A saved chunk-notes file's "Notes missing" marker (`internal/notes/chunknotes.go:83-127`, task 4-11) then names `` `api/handler.go api/handler.go` ``, a path that matches no file, in the file the operator or an agent acts on after the run. A whole-file part names its files through `headerPath` (`internal/notes/chunknotes.go:124`); a piece names `p.file`, which `cutParts` also takes from `headerPath` (`internal/notes/chunk.go:389`), so both carry the doubled name. The same doubled name reaches the AI in piece framing (`internal/notes/chunk.go:546-550`) and keys the chunk sort.
**Solution**: Pin the prefixes in `AssembleRange`'s argv (`internal/notes/assemble.go:178`): `git diff --src-prefix=a/ --dst-prefix=b/ <range> -- . …`. Every header then takes the `a/P b/P` form `headerPath` already reads, whatever the operator's prefix config, and the marker, the piece framing and the sort key are all fixed in one place. Drop the no-prefix clause from `headerPath`'s doc comment, and update the tests that pin the exact diff argv. Pinning the argv was chosen over teaching `headerPath` the unprefixed `P P` form, because only the argv fix also covers custom src/dst prefixes and `diff.mnemonicPrefix`: command-line prefixes override git's diff prefix config.
**Outcome**: Under any diff prefix config, a saved file's marker, the piece framing and the chunk order name each file by its repo path. Every release and regenerate diff read sets `a/` and `b/` on the command line, so under git's default prefix config the diff mint reads is the same as today's.

**Acceptance Criteria**:
- [ ] A forward release reads its diff with `git diff --src-prefix=a/ --dst-prefix=b/ {lastTag}..HEAD -- . :(exclude)CHANGELOG.md`, followed by the configured `diff_exclude` globs and, in plain mode, the `version_file` exclude, in today's order
- [ ] A regenerate of one version, and each version of a `regenerate --all` batch, reads its `{PreviousTag}..{Tag}` diff with the same two prefix flags ahead of the range and the same exclude pathspecs after `-- .`
- [ ] The Change Map's `--name-status` and `--numstat` reads keep their current argv, with no prefix flags
- [ ] A failed chunked run over prefixed headers (`diff --git a/api/handler.go b/api/handler.go`) that leaves `api/handler.go` without notes saves a file whose marker names `` `api/handler.go` ``, or `` `api/handler.go` (partly) `` when only some of its pieces failed
- [ ] A piece cut from that file is framed as a piece "of the diff for api/handler.go", and the file packs in path order under `api/handler.go`
