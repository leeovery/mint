# Consolidation Tasks: Token Aware Diff Sizing (Phase 1)

## Task 1: One composition rule for a failed AI call's captured output
placement: phase 1
severity: duplication

**Problem**: Release (`notesFailureOutput`, `internal/engine/release.go:1640-1673`) and commit (`aiFailureOutput`, `internal/commit/run.go:797-812`) each hold a byte-identical copy of the rule that turns a failed AI call's two captured streams into the text shown beneath mint's line: a stream counts only when non-blank after trimming, stdout before stderr, joined by one `\n`, trailing whitespace trimmed. Each copy is pinned only by its own package's tests (`internal/engine/notesfailureoutput_internal_test.go`, `internal/commit/run_aifail_output_test.go`), and nothing ties them together: `aiFailureOutput`'s doc (`run.go:797-799`) claims the two match, and nothing checks it. Phases 2 and 4–7 rework release's ✗ line around `notesFailureOutput`; if its rule changes there, commit silently keeps the old layout and the same tool failure (a claude too old for the lean flags above all) reads differently on the two verbs, which task 1-5's criterion ties together ("as it does beneath release's ✗ line").
**Solution**: Move the rule onto the carrier as one method beside `GenerationError` in `internal/ai/transport.go` (e.g. `func (e *GenerationError) Output() string`), its doc moving there from `release.go`; `Stdout`/`Stderr` stay raw. `notesFailureOutput` keeps its name and both helpers shrink to `errors.As` plus the method call, so `notesfailureoutput_internal_test.go` and the later tasks that cite `notesFailureOutput` by name stay valid; the `unicode` imports go with the copies. The "composition is a downstream concern" comments on `GenerationError` (`transport.go:53-56`) and in `Generate` (`:231-232`) and `aiFailureOutput`'s cross-reference to `notesFailureOutput` change in the same edit. Behaviour is unchanged on both verbs — derived from the finder's proposed shape and the bank's four matching entries.
**Outcome**: One rule, owned by the `ai` package, composes the captured output for both verbs, so a change to it reaches release's ✗ line and commit's warning together.

**Acceptance Criteria**:
- [ ] A forward release whose notes call fails on both attempts with `Prompt is too long\n` on stdout shows `Prompt is too long` beneath its ✗ line, and a regenerate failing the same way shows the identical text, as before the change
- [ ] A commit whose AI call fails on both attempts with `error: unknown option '--safe-mode'\n` on stdout (a claude too old for the lean flags) carries `error: unknown option '--safe-mode'` beneath the attended `could not generate a message, opening editor` warning, beneath the unattended (`-y` or non-TTY) `no AI message and no interactive editor available` line, and beneath the warning when an `r` regeneration fails the same way, as before the change
- [ ] With both streams non-blank, the text beneath mint's line is stdout then stderr, joined by one newline, interior content verbatim, trailing whitespace trimmed, on both verbs: stdout `Prompt is too long\n` with stderr `warning: retrying\n` reads `Prompt is too long\n\nwarning: retrying`
- [ ] A whitespace-only stream counts as empty on both verbs: whitespace-only stdout with stderr `Credit balance is too low\n` reads `Credit balance is too low` with no leading newline, and two whitespace-only streams render no output block
- [ ] A cause that carries no captured streams (a timeout, a missing binary, an oversized diff, a plain error) renders no output beneath mint's line on either verb
- [ ] A failed call's `ai.GenerationError` still holds `Stdout` and `Stderr` exactly as the command wrote them (a whitespace-only body byte-for-byte), and neither helper reads the streams any more: `rg -n 'genErr\.(Stdout|Stderr)' --type go -g '!*_test.go'` returns nothing (5 hits today: `internal/engine/release.go:1664`, `:1665`, `:1667`, `:1668`, `internal/commit/run.go:806`)
