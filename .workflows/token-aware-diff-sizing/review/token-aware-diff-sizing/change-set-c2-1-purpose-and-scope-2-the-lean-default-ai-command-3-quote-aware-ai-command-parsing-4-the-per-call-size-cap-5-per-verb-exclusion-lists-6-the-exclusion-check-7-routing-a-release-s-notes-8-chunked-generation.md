FINDINGS:
- [out-of-scope] internal/presenter/plain.go:421 — With plain mode on an interactive stdin (`--plain` at a terminal, or `mint release | tee log`), an exclusion pause cannot be interrupted until Enter is pressed. `Prompt` blocks in `readChoice`'s `reader.ReadString('\n')` (internal/presenter/prompt.go:87) and takes no context. `exclusionPauses.Pause` drops the one it is given (internal/engine/release.go:1190). Ctrl-C is caught by `signal.NotifyContext` (cmd/mint/main.go:74), which only cancels ctx, so the read stays blocked and repeated Ctrl-C does nothing. Only when the operator presses Enter (read as the default, keep) or sends EOF does `ExclusionCheck.pause` see the cancel (internal/notes/exclusioncheck.go:185) and the run abort, recording nothing. The defect predates this work and affects every plain-mode gate (review gate, version confirm, the floor's choice). The new pauses inherit it. Fixing it means making the presenter's line reads cancellable (a ctx-aware `Prompt`/`AskLine` that returns when ctx ends), which touches every gate. — FAILS: §6.6's "Ctrl-C during the pauses cancels the run" does not hold in plain mode. To the operator, the run looks hung at the pause after Ctrl-C until they press Enter, and the Enter itself reads as an answer before the cancel is noticed.
